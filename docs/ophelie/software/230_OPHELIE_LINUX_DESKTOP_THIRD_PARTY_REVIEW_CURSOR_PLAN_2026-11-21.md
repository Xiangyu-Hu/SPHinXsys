本轮交付：一个 Ubuntu/Linux 桌面软件、两个甲方示例项目、真实短跑及结果回放、可安装/解压运行的发行包。

## 0. 已确定的决策：直接执行，不再等待范围选择

用户已明确：近期只需要 Linux 软件，首轮功能尽可能完整，用于第三方审查。首轮不能仅交付 STL 查看器、结果播放器或 CLI。

必需操作流程：

**打开项目 → 装配查看 → 参数编辑/检查 → 生成并查看实际粒子 → 启动真实计算 → 时间步/日志监控 → 正常停止或完成 → 结果查看/导出 → 保存和重新打开项目及历史结果。**

两个项目分别完成这条流程。历史结果回放同时提供，现场可组合“真实短跑+历史结果回放”，必须清楚标识。

- Linux/NVIDIA SYCL GPU 为优先后端；Windows、Windows SYCL CPU 移植及打包暂停。
- 采用 Qt 6 Widgets + VTK + CMake，沿用原任务书架构，不重新设计另一套软件。
- 使用独立求解进程；统一 `coldcrucible-solver` 适配入口包装已有预处理/求解目标，GUI 使用同一入口。
- 暂无成熟能力时如实显示，不由软件机重写物理算法或用动画替代计算。
- 分阶段提交中间成果，但本任务最终完成标志是两个真实项目的软件运行闭环和 Linux 包复测通过。

## 1. 文件关系和交接能力核对

配套输入：原桌面任务书、228 弹性桨补充、最新版229甲方回复与材料规则、物理机实际交接包、甲方STL及物性原始资料。

本文件细化软件交付范围；最新229决定甲方数据与物理目标，228决定真实弹性桨要求。整圈与物理定量验证按实际证据分别标识，不因原计划旧表述卡住短跑软件接入。

软件机转述的交接摘要如下，开工须检查原始配置/日志并在本机复跑，不直接把摘要当最终验证：

| 项目 | 摘要中可接入的能力 | 不可扩大的结论 |
|---|---|---|
| 自然对流 NC | 静水、ΔT=20 的首轮短测 | 不代表热电偶1000℃定量通过，也不等于所有加热路径已通过 |
| 搅拌 | elastic_driven，E0–E2短窗、F0、F1 | E2不是整圈；F1如为规定热源，不是真实EM耦合 |
| 材料 | 冻结mu，参考1273.15K；借用sigma16 | 不称已启用完整mu(T)/sigma(T)，不称甲方实测sigma |
| 工况 | 10rpm，频率先100kHz，电流unknown | 30kW为电源输入，不能直接写成熔体吸收30kW |

如果甲方随后提供新的电流/电压或实验数据，作为新配置版本接收；不得静默覆盖本轮已复跑的基线。

5. 两案在本机的真实短跑记录：退出状态、物理时间、实际设备、产物及墙钟耗时。

GPU枚举不是GPU求解通过。核对设备实际执行路径；若固体亚步为CPU/GPU混合，明确记录，不能一概称全GPU。

## 3. 代码组织与两机协作

软件机使用独立工作区/构建目录，可采用 `ophelie-software-linux`。物理机使用独立验证分支，集成分支仍为 `feature/EM-Biot-Savart`。无需迁入SPHinXsim，不影响独立A-phi/Laplace分支。

软件机负责：界面、配置解析/校验、适配层、文件索引、包和软件回归。

物理机负责：材料、弹性/FSI、电磁与浮力验证、算子稳定性和后续定量物理修复。物理机已交接的功能先复用，软件机不重复实现弹性桨。

共享CMake、case入口、参数默认值和输出字段变化须明确说明。可独立提取的通过提交才选择性集成；关联提交不能遗漏。审查包固定SHA，不能自动追随物理分支最新状态。

独立 build、install、prepare、run 目录；不通过双向网盘实时覆盖源码和运行输入。保留用户现有改动，不硬重置、不强推。

## 4. 统一CLI与配置契约

建议入口（名称可沿原计划，语义必须统一）：

```text
coldcrucible-solver info --json
coldcrucible-solver validate --config <case.json>
coldcrucible-solver prepare --config <case.json> --output <prepared-dir>
coldcrucible-solver run --config <case.json> --prepared <prepared-dir> --output <run-dir>
```

允许轻量适配可执行程序或随包适配层调用原有test binary；不要求把所有求解目标合并成一个巨大C++程序。适配层及依赖必须随包，用户侧无需安装编译器或手动配置开发环境。若适配层使用Python，必须处理随包运行时或明确可安装的运行依赖，不能偷偷依赖开发机虚拟环境。

GUI不分散硬编码不同test目标的路径/参数。旧求解器CLI可保留，适配层建立显式映射并检查不支持字段。不能忽略用户输入后仍报成功。

| 文件/接口 | 必需内容 |
|---|---|
| info | GUI/求解器版本、schema版本、实际可用设备、支持模型/字段及不可用原因 |
| case.json | 项目用途、装配和变换、材料及来源、热初态/边界、源模式、搅拌、分辨率/时长/输出、后端 |
| validate | 字段路径、severity、错误代码和说明；校验数据/几何/模型兼容性 |
| prepared.json | 输入指纹、预处理版本、求解体角色/粒子数、Reload与可视化文件及有效模式 |
| effective-case.json | 本次实际生效参数，含单位转换、默认值、借用值、限制和实际物理路径 |
| events.ndjson | start/stage/progress/warning/error/end，逐行结构化事件 |
| result-index.json | 完整帧文件、真实物理时间、体/字段/单位、曲线、运行模式及状态 |
| summary.json | 版本、设备、计时、退出/取消/失败状态、实际到达时间、可用诊断和验证范围 |

交接effective文件作为基线，不直接冒充通用case输入。若采用转换脚本，保存转换规则并验证关键字段一致。新运行每次生成独立effective快照。

### 4.1 项目结构与缓存

```text
project/
  case.json
  assets/
  materials/
  prepared/<fingerprint>/
  runs/<run-id>/
    effective-case.json
    summary.json
    events.ndjson
    solver.log
    result-index.json
    results.pvd
    probes.csv
    frames/
```

项目内相对路径，安装目录只读也能运行。新建运行目录不可覆盖历史数据。另存/复制项目时应带上依赖文件或明确提示缺项；移动项目后仍可打开。

缓存指纹包含实际计算几何与变换、液深、搅拌开关、力学模式、固体/流体间距、初始桨位、夹持区及预处理版本。显示水冷管、透明度、输出间隔改变不应无故使几何粒子缓存失效。

## 5. 一个窗口、两个示例项目

计算模式唯一来源为 `stirring.enabled`。项目名称可以不同，但不再新增第二个独立模式开关控制求解。

| 状态 | 求解行为 |
|---|---|
| 关闭搅拌 | 无求解桨，不扣桨体积；已导入桨只可作为明确标记的参考预览 |
| 开启，弹性桨有效 | 采用elastic_driven、驱动区及实际流固接触；按真实变形粒子更新边界 |
| 开启但缺桨/材料/夹持区/可用后端 | 阻止prepare/run，定位缺项；不静默降级为刚性桨 |

切换只影响下一次准备/运行；当前结果仍按原模式打开。当前项目开关切换不等于加载另一套装配。两案热电偶、STL和预设来自各自项目，不串件。

关闭搅拌时不模拟“浸没静止桨”，除非另有已实现模式；不临时增加。

## 6. 桌面功能要求

### 6.1 项目和装配

提供新建、打开、保存、另存；两个现成示例可一键打开。显示项目名、用途、当前模式和版本。

左侧树区分：流体、数值壁、弹性桨、线圈源展示、冷却管展示、热电偶/测点。支持导入/替换STL、显隐、透明、选择和角色查看。

统一单位和4×4变换驱动装配、粒子、测点、重力和桨轴。支持相机旋转/缩放/重置、坐标轴、至少一个可交互剖切平面。通过已知点/包围盒及剖面验证对齐。

STL可预览范围可以宽于求解支持范围。任意几何预览成功不等于任意几何可计算；超出已有圆柱/装配模板支持时明确校验失败。

水冷管显示与等效热冷却独立，显隐不改变求解。水冷管不自动加入EM导体或流固接触。

### 6.2 参数面板

基本/高级分组，带单位、范围和来源。至少包含液深、初温或已支持温场、材料、热边界、加热模式、10rpm及旋向/启动斜坡、分辨率、时长、输出间隔、实际设备。

只开放求解器实际支持字段。运行时锁定本次输入；允许查看旧结果但不污染当前任务。参数变更后显示未保存及缓存失效状态。

材料来源区分甲方确认、法国借用、开发假设、未知。内部SI，℃到K、rpm到rad/s、mm到m仅转换一次。

物性按最新版229：mu=exp(-4+8500/T)，甲方sigma新公式为exp(4.5-8500/T)，不能使用旧pow10解释。但本次交接若使用冻结mu及sigma16，首轮保留该已测配置；界面不因支持材料编辑就宣称已通过温变路径。

固定温场、规定热源、固定EM空间Q、在线EM/反馈是不同模式。按实际运行显示；不支持的模式不可选。电流unknown时，给定电流模式不能假装输入已确认；规定热源开发模式可独立使用。

### 6.3 粒子预处理和显示

从GUI实际执行prepare，产生求解器读取的Reload/等价输入及同来源可视化。显示求解体分组、数量和dp。允许渲染降采样，但显示已显示/总数，不能修改求解粒子。

检查装配重合、有桨初始体积扣除、固体厚度/连通与夹持区、最小间隙。复用物理机成熟预处理，不在GUI里另写一套视觉点云代替。

允许命中匹配缓存，明确显示缓存来源；验收至少做一次实际新生成，不能只展示预存点云就标预处理通过。

### 6.4 启动、停止与运行状态

使用异步QProcess及独立参数列表，不把用户路径拼入shell字符串。处理stdout拆包/多行、stderr日志、空行/坏事件和未知可选字段。结构化stdout与普通日志分开。

GUI状态至少区分idle、validating、preparing、running、stopping、completed、cancelled、failed。进程未启动成功不能显示running；退出码非零不能仅凭文件存在显示completed。

若调用多个子进程，所有子阶段纳入生命周期。停止需传至实际求解进程，避免孤儿GPU任务；首选取消文件/stdin协作停止，在可控边界写出取消状态及已完成帧。必要强制终止标明interrupted/failed，不假称正常停止。停止不承诺断点续算；避免不对应真实能力的“暂停/恢复”按钮。

退出GUI时如有运行任务，明确提示并处理，不遗留未知后台作业。首轮默认一次一个活动求解任务，避免GPU资源争抢。

### 6.5 时间步、日志与残差

显示真实物理时间、设定结束时间、墙钟时间、阶段、实际设备和最近输出时间。计算进度按实际时间推进；无已知工作量的预处理显示忙碌，不伪造百分比。

步长曲线注明声学/外层/固体亚步类型。仅采样必要频率，日志批量刷新，不在每个GPU子步为画曲线强制同步。

残差仅在实际求解迭代时显示，并记录定义、归一方式、容差、迭代数及收敛状态；没有GMRES或没有输出则显示未启用/无数据，不绘制模拟下降曲线。密度偏差、温升、能量残差使用各自名称。

### 6.6 结果、回放和导出

内置VTK能查看实际粒子场、温度/速度、切片及有单位色标；时间滑块使用保存的真实时刻。可实现矢量显示；若提供流线，须使用适用的矢量场插值和有效域，不以箭头或不连贯粒子积分冒充已验证流线。

弹性桨显示实际固体状态，提供已有且定义清楚的位移/弹性偏移、速度和应力。von Mises必须来自物理应力的正确计算，不以任意应力范数替代。缺失字段标不可用；若须新增输出，由物理侧确认定义并作最小验证。

结果页提供测点温度曲线、运行摘要、字段选择、截图、CSV及VTK数据导出；有扭矩等真实曲线时可显示，不能伪造或混淆驱动反力与流体扭矩。

新帧写完后才原子更新可读索引，GUI不读取半写文件。运行中查看已完成帧和结束后重开历史结果均需通过。缺一帧或损坏文件能定位说明，不整个界面崩溃。

外部ParaView一键打开PVD可保留；未安装ParaView时，内置显示仍能完成基本审查。

## 7. 科学结论与软件状态分开

| 显示内容 | 正确含义 |
|---|---|
| 真实短跑通过 | 当前输入/版本/设备成功推进并输出，不代表物理误差全部达标 |
| 弹性桨已接通 | 自由区确有弹性求解，不是整体刚体动画 |
| E2短窗 | 不等于一整圈；10rpm匀速一圈为6s，斜坡需积分判定 |
| 固定EM空间Q | 热源来自某次EM计算，不等于在线sigma(T)反馈 |
| 规定热源/固定温场 | 开发诊断，不能标真实EM求解通过 |
| 1000℃测点目标 | 待按实验时刻/稳态条件定量对比，不将初态设1000℃后授予PASS |
| 1400℃搅拌信息 | 当前定性目标，位置/时刻/功率条件仍需明确 |
| 30kW | 电源输入，界面与账本不得标成玻璃实际吸收 |

这些信息放在运行摘要/能力说明中简明呈现，不把历史轮号和算法排障细节堆入普通用户操作页。

## 9. 软件验收矩阵：每项必须有实际记录

状态只能为PASS/FAIL/BLOCKED/NOT_RUN，不能以“应该可用”标PASS。UI自动测试可补充错误路径，但实际求解通过只能来自真实求解器。

| ID | 操作 | 判据与证据 |
|---|---|---|
| A01 | 安装/解压后启动 | GUI及solver启动，无缺库；记录系统、设备与版本 |
| A02 | 打开两个项目 | 装配、模式、参数和测点不串案 |
| A03 | 编辑一个支持参数后运行 | effective值确实变化，保存/重开保留；不要求物理量一定显著变化 |
| A04 | 实际生成粒子 | 两案prepare可用，至少一次新生成，统计与求解输入一致 |
| A05 | NC真实短跑 | GUI启动并正常完成，有真实时间/日志/温度速度产物 |
| A06 | 弹性搅拌真实短跑 | 实际elastic_driven路径，固体推进有效且结果可读；不要求现场整圈 |
| A07 | 正常停止 | 停止请求作用到求解进程，无孤儿任务，状态正确，完整帧仍可读 |
| A08 | 错误输入 | 缺STL、非法数值/缺桨拦截并定位，不伪造成功 |
| A09 | 运行失败 | 真实子进程失败向GUI传播，显示原因且保留已有证据 |
| A10 | 搅拌开关往返 | 无桨/有桨缓存隔离，缺桨阻止启动；旧结果模式不改变 |
| A11 | 项目和结果重开 | 关闭程序后重开，真实时间轴/字段/单位及曲线正确 |
| A12 | 路径与迁移 | 中文、空格路径；复制/移动项目后相对依赖有效 |
| A13 | 输出与导出 | CSV可读、VTP字段一致、截图/色标有效；无ParaView仍可查看 |

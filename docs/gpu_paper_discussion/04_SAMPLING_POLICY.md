# 数据记录频率政策（论文够用性）

日期：2026-11-03  
问题：各类数据记多密？按 V2 默认够不够写 GPU 论文？  
结论先说：**性能主表不靠高密度时间序列；A 组物理曲线才需要足够密的探针。V2 方向够用，但具体 Hz/Δt 必须在每个 case 冻结前写死——本文件给出默认值，先导后可微调并升 revision。**

---

## 1. 按数据类型：记什么、多密、够不够

| 数据类型 | V2 说法 | 本分支默认频率 | 论文用途 | 够不够 |
|---|---|---|---|---|
| **wall_solver / 阶段计时** | 固定物理窗口汇总；阶段互斥累计 | **每 run 一套汇总**（窗口起止各同步一次）；阶段为累计墙钟，不是每步曲线 | 加速比、瓶颈饼图、scaling | **够**（GPU 论文核心） |
| **step_stats** | 块汇总，不必每步写盘 | 每 **N_outer 块**或每 **Δt_phys≈0.01–0.05×窗口** 写一行（dt min/mean/max、各级步数增量） | 附录/方法：自适应步、工作量口径 | **够**；不要每步写盘 |
| **body_stats / 邻居数** | 采样时刻；高开销不每步回传 | 窗口内 **5–11 个物理时刻**（含起、中、止）；MNIPS 用采样邻居×步数估计 | 规模表、MNIPS 口径 | **够**；过密会污染 benchmark |
| **telemetry（显存/功率/温度/利用率）** | 约 **1 s** 墙钟外部采样 | **1.0 s**；短窗 \<10 s 可改为 **0.2–0.5 s** | 峰值显存、是否降频、资源表 | **够**；不必亚秒除非短窗 |
| **A 组 probes（物理验证）** | fixed sample schedule，未给 Hz | 见 §2（按物理时间） | 曲线图、频率/幅值、与参考对比 | **关键**：必须够画图与 FFT/周期统计 |
| **B 组最低诊断** | 摘要级 | 与 body_stats 同档，或窗口末一次完整摘要 + 中点一次 | 证明跑的是同一物理，非新验证章 | **够**（性能章） |
| **C 组最低诊断** | **低频** | 另分支；建议每 **0.05–0.1×窗口** 或每转/每晃荡周期 **4–10 点** | 跨硬件一致性核查 | 工业章够；不是完整物理论文 |
| **场输出 / 界面帧** | validate / showcase | validate：**稀疏代表帧**（A4/A5 等 6–20 帧）；benchmark：**0 或 1 帧**；showcase 另开 | 插图，非主表 | 插图够；勿在 benchmark 高频写 VTK |
| **性能重复** | 同配置 ×3 | 3 次取 median/min/max | 报表误差棒 | **够**（时间重复，非物理样本） |

要点：GPU 论文主图是 **scaling / speedup / stage / memory / group**，这些是 **每配置几个标量**，不是高频示波器。物理正确性章才需要 **时间序列**。

## 2. A 组物理探针默认（按物理时间）

原则：采样间隔应能分辨关心的最快动态，并保证后处理（FFT、峰值到达）稳定；**跨 CPU/GPU 必须同一物理时刻表**（或同一 Δt_sample），禁止靠 DTW 对齐相位。

| Case | 关心量 | 建议探针 Δt（物理） | 额外输出 | 说明 |
|---|---|---|---|---|
| **A1** Poiseuille | u_center(t)、Q(t)、质量收支；终态 u(y) | 瞬态段 Δt ≈ **0.01–0.02 T\***；近稳态可放稀到 **0.05 T\***；剖面只在预定稳态时刻写 **1–3 次** | 进出口累计质量每探针时刻 | T\* = 特征对流/粘性时间；稳态比不需要密到每步 |
| **A2** 梁 | 尾端 x/y(t)、能量 | ≥ **20–40 点 / 振动周期**（典型每周期 ≥32 点） | 跑够多个稳定周期再算频/幅 | 频率误差目标 ~1% 量级时，周期采样不足会假误差 |
| **A3** 窗框 | 测点 T、热流、残差 | 伪时间/推进：每 **N_iter**（如 10–50）或残差降一量级记一点；近稳态加密判定 | 终态剖面 + 内外热流 | 比的是稳态与收敛，不是高频热波 |
| **A4** 两相溃坝 | p(t)、前沿、质量 | 压力探针 Δt 足以抓住峰值上升（建议 **≤ 0.001–0.005** 无量纲时间，或每声学步块汇总峰值） | 界面帧 8–15 张均匀/关键时刻 | **峰值到达时间**对采样敏感；宁密一点 |
| **A5** FSI2（后置） | 尾端轨迹、载荷 | 同 A2：≥ **20–40 点 / 周期**；稳定周期段统计 | 代表变形帧少量 | 与文献比频率/振幅 |

场文件（VTK 等）：validate 模式稀疏即可；**不要**为论文把每步粒子场都写出——会拖慢、占盘，且 benchmark 不可比。

## 3. B 组性能跑：默认「稀诊断 + 密计时累计」

| 模式 | 物理/诊断写盘 | 计时 |
|---|---|---|
| **benchmark**（主加速比） | 最低诊断：起、中、末或固定 5 点；**无**高频 VTK | 窗口 wall_solver + 阶段累计；I/O 单独计或关闭 |
| **profile**（代表规模 1 点） | 同 benchmark 或略多 | 可加同步分段，**标记开销**，不进主 speedup |
| **validate**（B 组一般不做全套） | 若需质量曲线：B1 每 50–100 次松弛记残差；B2/B3 稀疏探针 | 不与主表混用 |

B1：固定迭代（如 1000）时，残差/质量可每 **50** 次记一点；「到达阈值的迭代」另记事件时刻即可。

## 4. 和「写文章」的映射：缺不缺？

| 论文常见图表 | 数据来源 | 当前政策 |
|---|---|---|
| CPU/GPU 加速比表 | wall_solver ×3 | 够 |
| 弱/强规模曲线（N vs time/MPPS） | 五档汇总 | 够 |
| 阶段占比堆叠图 | stage_timing | 够（注意互斥、勿父子双加） |
| group size 敏感性 | L3×{32,64,128,256}×3 | 够 |
| 显存–N 曲线 | peak_vram + telemetry | 够（1 s 采样抓峰值通常够；短窗加密） |
| 精度：剖面/测点误差表 | A 组终态 + 参考 | 够 |
| 精度：时间历程 / 频率幅值图 | A 组 probes | **够，前提是 §2 密度落地** |
| 功率/利用率（可选） | telemetry 1 s | 够作补充，非必须 |
| 工业扭矩/温度长曲线 | C 组低频诊断 | 另分支；作一致性即可，不作完整工艺论文 |

**不够、必须先导补冻结的只有：**

1. 每个 A case 的 **具体 Δt_sample / 输出时刻表**（写进配置与 manifest 的 `output_schedule`）。  
2. A4 压力峰若采样过稀，到达时间误差会假大——短测时用更密一档核对峰值是否稳定。  
3. benchmark 若误开高频 VTK，计时会脏——模式必须分开。

**刻意不追求的（避免过度采集）：**

- 每步粒子场、每步邻居全量回传  
- 把 C 组诊断做成新物理验证章  
- 用 telemetry 亚毫秒采样「优化 kernel」（那是 profile 工具的事）

## 5. 冻结检查清单（每个 case 正式跑前）

- [ ] `output_schedule`：探针物理时刻或 Δt、场帧列表、单位  
- [ ] validate vs benchmark 两套 schedule 分开；跨设备同 mode 同 schedule  
- [ ] A2/A5：确认稳定段周期数 × 每周期点数 ≥ 做 FFT/峰值统计所需  
- [ ] A4：短测对比「密采样 vs 正式采样」峰值/到达时间差是否可接受  
- [ ] telemetry 周期写入 `run_manifest`（默认 1.0 s）  
- [ ] 邻居/MNIPS 采样时刻与「是否计入 wall_solver」写明  

先导后若改采样密度且影响可比性 → 升 `experiment_revision`，旧 run 不混进主表。
